# Análisis de huecos (`investigacion/huecos.md`)

1. **Huecos**: para cada columna de la matriz, qué combinación casi nadie cubre (p. ej. controladora original + MQTT + gemelo intercambiable + métricas). Cada hueco con los trabajos que lo evidencian.
2. **Filtrar** los huecos que este proyecto puede cubrir de verdad con un RV-M1, una placa puente y el tiempo de un docente.
3. **Aportaciones** (máx. 3–4), redactadas como afirmaciones verificables.
4. **Preguntas de investigación** (PI1, PI2…) ligadas a cada aportación.
5. **Evidencia necesaria**: qué experimento y qué métrica responde cada PI (enlaza con `diseno-experimental`).
6. **Riesgos para la novedad**: trabajos que más se parecen y cómo diferenciarse.

Formato: tabla Hueco → Evidencia (claves) → Aportación → PI → Experimento/métrica.
